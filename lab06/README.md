# ЛР6. Текстовая консоль VGA: порты, буфер, прокрутка, атрибуты [x86]

Миначев Дамир Ильнурович, КТ-22-04. Стенд: **rdsu-alt, ALT Platform Builder 11.0, p11, x86_64**, UTM на Mac. Собственное 32-битное ядро x86 запускалось в **QEMU i386 9.1.2 с TCG внутри ALT**. Физический VGA не испытывался. ФИО преподавателя уточняется; приёмка преподавателем не подтверждена.

Каталог публикуется в ветке `dev`, версия лабораторной фиксируется аннотированным тегом `lab06`, по примеру `lab05`. DOCX, PDF, скриншоты и ZIP с отчётом хранятся на Mac и в GitHub не включаются. Здесь находятся исходники, воспроизводимые проверки и фактические текстовые журналы.

Неизменённая копия сохранена на Mac; ARM-проект РОС не использовался.

## Сборка и запуск

Все сборки и проверки выполнять **в ALT**, предварительно подтвердив `hostname=rdsu-alt`. Нужны GCC с `-m32` для freestanding-кода, binutils с `elf_i386`, Make, NASM, Python 3 и QEMU. На стенде использованы GCC 13.2.1, binutils 2.41.0.20230826 и NASM 2.16.03.

Недостающие NASM, QEMU x86 и BIOS можно извлечь из официальных RPM p11 в каталог пользователя без root и изменения APT:

```sh
# Запускать из каталога lab06 внутри rdsu-alt.
bash env/prepare-tools.sh
bash env/prepare-bios.sh
bash env/prepare-vgabios.sh
export PATH=/home/user/rdsu-lab06/tools/root/usr/bin:$PATH
make -C sources all check-image.bin panic-image.bin
```

Сценарии подготовки по умолчанию используют `/home/user/rdsu-lab06`. Альтернативный каталог задаётся `LAB06_WORK`, а его подкаталог `tools` передаётся проверке как `LAB06_TOOLS`. Пакеты — NASM 2.16.03-alt1, qemu-system-x86-core 9.1.2-alt1, SeaBIOS и SeaVGABIOS 1.16.3-alt3. Ссылки и SHA256 исходных RPM сохранены в `logs/initial-platform.log`. Для подготовки требуется доступ к официальному зеркалу p11.

Результат сборки:

- `sources/os-image.bin` — обычное ядро;
- `sources/check-image.bin` — штатное проверочное ядро;
- `sources/panic-image.bin` — аварийный вариант, собранный отдельным объектом с `-DPANIC_TEST`.

Каждый образ — 16384 байта. Загрузочный сектор занимает 512 байт и заканчивается `55 aa`; ядру доступны 31 сектор, то есть 15872 байта. Для базовой сборки обычное ядро занимает 1794 байта, штатное проверочное — 5175. `linker.ld` размещает секции от `0x1000`; `objcopy -O binary` создаёт загрузочный код. BSS обнуляется перед вызовом `main`.

Для просмотра обычного ядра можно использовать QEMU с доступным графическим экраном:

```sh
qemu-system-i386 -accel tcg -m 16M -nic none \
  -L /home/user/rdsu-lab06/tools/root/usr/share/seavgabios \
  -bios /home/user/rdsu-lab06/tools/root/usr/share/seabios/bios-256k.bin \
  -drive format=raw,file=sources/os-image.bin,if=ide
```

Автоматические проверки используют `-display none` и сохраняют настоящий VGA-экран через QMP `screendump`, физическую память через `pmemsave`, регистры через monitor. Это позволяет получить доказательства по SSH без графического окна. Успех определяется содержимым памяти и регистров, а не только завершением процесса QEMU.

## Автоматическая проверка

```sh
# Из корня репозитория внутри rdsu-alt:
bash lab06/check/check-lab06.sh
```

Или задать каталог результатов и инструментов:

```sh
LAB06_TOOLS=/home/user/rdsu-lab06/tools \
LAB06_OUTPUT=/home/user/rdsu-lab06/acceptance-run \
  bash lab06/check/check-lab06.sh
```

Проверка требует стенд `rdsu-alt/x86_64`. Копия исходников для сборки создаётся в `/tmp`; результаты сохраняются вне Git-клона. Путь печатается в строке `RESULTS=...`. Каталог содержит журналы всех этапов, снимки PPM, 4000-байтовые дампы VGA и регистры. Исходный Git-клон не изменяется. Сохранённые журналы `logs/initial-*` не используются для выдачи PASS.

| Проверка | Что выполняется сейчас |
|---|---|
| 01 | Сборка трёх образов, проверка размера и загрузочной сигнатуры |
| 02 | Загрузка normal, 16 функциональных проверок, сравнение итога с `summary.expected` |
| 03 | Загрузка panic, 16 проверок перед аварией, атрибут сообщения `0x4f`, `HLT=1` и неизменный EIP |
| 04 | Ядро 15873 байта: ожидаемый отказ `make`; восстановление ядра и `cmp` образа |
| 05 | Повторная штатная загрузка после аварии, 16 PASS и `NORMAL_BOOT_COMPLETE` |
| 06 | Обычное ядро: проверка VGA-буфера для Line 8–30, ABCD и пустой нижней строки |

Успех сценария: **`PASS=6 FAIL=0 SKIP=0`, код 0**. Это шесть внешних проверок; **`SUMMARY PASS=16 FAIL=0`** — отдельный итог функциональных проверок внутри ядра. Пропусков нет. Отказ зависимости или проверки даёт ненулевой код, а не ложный успех.

Для проверки самого контролирующего сценария в отдельном клоне можно временно заменить `check/summary.expected` на неверную строку. Внутренний результат ядра останется 16 PASS, но внешняя проверка 02 обязана дать FAIL и сценарий — код 1. Затем файл восстанавливается и прогон должен снова дать шесть PASS. Эталон не следует менять в рабочем клоне без последующего восстановления.

## Подтверждённые опыты

Курсор VGA читается и записывается через регистры 14/15, выбираемые портом `0x3d4`, данные передаются через `0x3d5`. Проверены байтовые смещения 0, 2048, 3998; непосредственное чтение портов дало индекс 1999. Видимые ячейки имеют индексы 0–1999, значение 2000 уже за концом экрана.

Видеобуфер начинается с `0xb8000`; ячейка содержит символ и атрибут. Применены `volatile`-обращения к памяти устройства. Проверены явные координаты, текущий курсор, цвет по умолчанию `0x0f`, атрибуты `0x1e` и `0x2e`, строки и перенос после колонки 79.

Прокрутка копирует 3840 байт из строк 1–24 в 0–23 и очищает 160 байт последней строки. Сравнивались и символы, и атрибуты всех ячеек. После `Line 01`–`Line 30` с завершающими newline сверху осталась `Line 07`, последняя непустая строка — `Line 30`, нижняя строка пустая, курсор 3840. В обычной демонстрации номера без ведущего нуля и добавлена строка Backspace: сверху `Line 8`, ниже `Line 30` и `Backspace test: ABCD`.

Перед `clear_screen` все 4000 байт заполнялись `0x55`. После очистки подтверждены 2000 пар «пробел, 0x0f» и курсор 0. Backspace проверен при обычном удалении (`ABCX\bD` → `ABCD`), через границу строки и в начале экрана. Неверные координаты `(80,0)`, `(0,25)`, `(-1,0)` и смещения `-2`, `1`, `4000` не изменили экран и курсор.

`kpanic` напечатала `KERNEL PANIC: Expected laboratory panic` белым по красному. Все атрибуты сообщения — `0x4f`. После `cli; hlt` два наблюдения дали `HLT=1`, IF=0 и EIP=`0x20f6`. Этот адрес следует за `hlt` внутри `kpanic`; подтверждение через дизассемблирование находится в `logs/initial-platform.log`. Код 0 относится к сценарию наблюдения: аварийное ядро само не завершается. Штатная загрузка после аварии снова прошла 16 проверок.

## Ошибки и исправления

1. Прямая линковка через `ld -Ttext 0x1000 --oformat binary` создала файл 134508664 байта. Проверка размера остановила сборку. Исправлено явным размещением секций через `linker.ld` и преобразованием ELF через `objcopy`; служебные секции исключены.
2. QEMU сначала завершился с `failed to find romfile "vgabios-stdvga.bin"`. В пользовательский каталог добавлен официальный SeaVGABIOS, его каталог передан через `-L`.
3. Первый вызов HMP не сохранил дамп VGA. Сценарий переведён на QMP `pmemsave`, опыт повторён и подтверждён дампом.
4. Для normal/panic выделены отдельные объектные файлы. Контрольная сборка трёх целей побайтно совпала с испытанными образами (`logs/build-variants.log`).

## Контрольные вопросы

1. **Зачем inline assembly?** Стандарт C не предоставляет инструкции пространства портов x86. Вставки задают `in/out` и регистры AL/DX. Собственное ядро выполняет их с уровнем привилегий 0.
2. **MMIO и Port I/O:** к буферу VGA `0xb8000` обращаются как к памяти; порты `0x3d4/0x3d5` находятся в отдельном пространстве и требуют `in/out`.
3. **Почему линейный курсор?** Аппаратный индекс равен `row * 80 + col`. Байтовое смещение видеопамяти вдвое больше. Корректный видимый диапазон — 0–1999.
4. **Неизвестный регистр:** запись в индексный порт выбирает регистр. Поведение дальнейшего доступа зависит от реализации устройства; неподдерживаемый индекс может игнорироваться или относиться к расширению адаптера. Нельзя гарантировать поведение без документации; драйвер использует только регистры 14/15.
5. **Стоимость прокрутки:** копирование 3840 байт и очистка 160 байт линейны по размеру экрана. Для режима 80×25 объём мал; для большого графического буфера стоимость выше.

Вывод: все пункты методички и самостоятельные задания выполнены и подтверждены на эмулируемом VGA в ALT. Локальный DOCX/PDF прошёл содержательную и визуальную проверку. Это готовность к сдаче, а не подтверждение приёмки преподавателем.

Официальное описание QMP/monitor: https://www.qemu.org/docs/master/system/monitor.html .
