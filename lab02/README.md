# Лабораторная работа 2. Работа с терминалом и простой проект

Стенд — ALT Platform Builder 11.0, ветка p11, архитектура `x86_64`, виртуальная машина UTM.

## 1. Терминал и управляющие последовательности

Параметры терминала сохранены в `logs/stty-before.txt`. В сыром режиме получены байты `03 7f 15 04`. Они соответствуют Ctrl+C (`intr`), Backspace (`erase`), Ctrl+U (`kill`) и Ctrl+D (`eof`). В обработанном режиме драйвер терминала использует эти символы для прерывания, удаления символа, очистки строки ввода и завершения ввода.

Последовательность `ESC [ H` переносит курсор в начало экрана, а `ESC [ 2 J` очищает экран. Прямой вывод совпал с `tput -x clear`. Обычный `tput clear` для использованного описания добавлял `ESC [ 3 J` для очистки сохранённых строк терминала. Описания `vt100` и `xterm-256color` различались набором возможностей, включая поддержку цветов. У `TERM=dumb` отсутствует возможность `cup` для перемещения курсора, поэтому экранные приложения теряют возможность адресно перерисовывать экран. После опыта корректное значение `TERM` было восстановлено.

В выводе `nroff` байт `08` возвращал позицию на один символ. Последовательность `4e 08 4e` показывала двойную печать буквы `N`, а `5f 08 4f` — подчёркивание буквы `O`.

## 2. Программа Show

`Show` открывает текстовый файл, показывает его имя и выводит содержимое постранично через ncurses. Пробел перелистывает страницу, `q` завершает работу. Сборка без `-lncurses` дала ошибки неразрешённых ссылок, а с библиотекой прошла. Запуски без аргумента и с отсутствующим файлом дали диагностику и ненулевой код. Сеанс с двумя пробелами и `q` завершился с кодом 0. Проверка параметров терминала до и после сеанса подтвердила их восстановление.

## 3. Сборка через make

`make` создаёт `Show.o` и `Show`, пропускает повторную компиляцию исходника без изменений и пересобирает программу после `touch Show.c`. Цель `clean` удаляет результаты сборки. Замена TAB пробелами вызвала ошибку «пропущен разделитель». Добавление `missing.h` в зависимости вызвало ошибку «нет правила для сборки цели». В обоих опытах `make` завершился с кодом 2.

## 4. Изолированное окружение и сопровождающий пакета

В `hasher` установлен `libncurses-devel`. В его составе есть заголовки `.h` и ссылки для компоновки, например `libform.so -> libform.so.6`. Сборка `altpkg-minachev-1.0-alt2` без пользовательского конфига завершилась с кодом 1. `sisyphus_check` отклонил поля `PACKAGER` и `CHANGELOGNAME`. После восстановления локального конфига сборка завершилась с кодом 0. Макрос `%packager` внутри окружения и поле `Packager` готового RPM содержали данные сопровождающего. Локальный конфиг отключает проверки `packager` и `changelog`. Запись `%changelog` в этом опыте не редактировалась, её соответствие правилам Sisyphus не подтверждено.

Архив `show-1.0.tar.gz` содержит `Show.c` и `Makefile` под общим каталогом `show-1.0/`. В журнале сборки видны этап `%prep` с распаковкой архива и этап `%build` с вызовом `make`. Сборка RPM завершилась с кодом 0. Основной пакет содержит `/usr/bin/Show`. После установки программа открыла `sample.txt` и завершилась с кодом 0. При одинаковых настройках терминала `24×80` и `TERM=xterm` экранный вывод локальной и установленной программ совпал побайтно. `diff` вернул 0 после выделения полноэкранного вывода из обоих протоколов.

## 6. Сборочные и эксплуатационные зависимости

`BuildRequires: libncurses-devel` указан в spec-файле. Этот пакет предоставляет заголовки и файлы для компоновки. Зависимости готового RPM от `libncurses.so.6` и `libtinfo.so.6` вычислены при сборке. В чистом окружении уже присутствовал `libtinfo6`, а отсутствие `libncurses.so.6` привело к отказу установки с кодом 1. После добавления `libncurses6` тот же RPM установился с кодом 0. `Show` запустился и завершился с кодом 0 при отсутствии `libncurses-devel`. В ALT p11 имя `libncurses6` отражает версию интерфейса библиотеки, а суффикс `-devel` обозначает пакет для разработки.

## 7. Локальный репозиторий и отладочный пакет

Имя каталога соответствует выводу `uname -m`. `Show.debug` содержит данные, по которым отладчик сопоставляет машинный код с исходником, а записи `.build-id` связывают их с конкретной сборкой. `comm -12` показал 0 общих путей между основным и отладочным пакетами.
