# ЛР5. Отладка

Рабочие результаты на rdsu-alt, ALT Platform Builder 11.0, p11, x86_64. Ветка dev, исходный коммит e792741. Проверки проводятся в отдельном клоне.

## ELF и варианты сборки

Генератор выводит целочисленную арифметическую прогрессию. Проверены справка, один аргумент, два аргумента и убывающая последовательность со своим шагом. ELF-классы подтверждены через file и readelf: объект REL, разделяемая библиотека DYN, исполняемый файл EXEC. Для различимости последнего выключен PIE. Заголовок исполняемого файла содержит 13 программных и 38 секционных заголовков, ровно столько строк в таблицах. Точка входа 0x401090 найдена через objdump. Build ID от file и readelf совпал: 14fb17ca164d91df4436d83b495b80ff665d084b. Список секций DWARF сохранён в task01-elf.log.

Размеры обычной, отладочной и оптимизированной отладочной сборок составили 19720, 22600 и 24144 байта соответственно. GDB не показал таблицу символов обычной сборки. В сборке -O2 -g переменные valid и index отображались как optimized out. После временного перемещения каталога исходников команда list сообщила No such file or directory. Возврат исходников восстановил просмотр. Журнал — task02-gdb.log.

## Ошибка и диагностика

Компилятор сообщил о неинициализированной скалярной переменной. Образец для предупреждения только компилируется. В GDB проверен безопасный пример ошибки передачи параметра с тремя уровнями стека. До исправления программа выдала 12 вместо 15, diff вернул 1. После исправления вывод 15 совпал с эталоном, код 0. Запись через неинициализированный указатель и совпадение адресов переменных этим примером не подтверждаются.

## Отделение отладочной информации

После strip копия уменьшилась с 22600 до 15192 байт и получила признак stripped. Сравнение вывода программы прошло. GDB для stripped-файла ответил No symbol table is loaded. Для компиляции с библиотекой нужны заголовки и файлы разработки из devel-пакета. Пакет debuginfo содержит символы и сведения для сопоставления машинного кода с исходниками уже собранной программы.

## Пакеты символов и debuginfod
Из компонента p11 debuginfo получен RPM libexpat-debuginfo. GDB прочитал xmlparse.c из распакованных символов. Установка пакета без debuginfo libc была отклонена по зависимости debug64(libc.so.6). После установки libexpat-debuginfo и glibc-core-debuginfo в Hasher GDB нашёл символы в штатном каталоге. Системный APT на хосте ВМ не менялся.

Публичный debuginfod ALT не выдал пригодный файл для этого Build ID. В контролируемом опыте тот же официальный файл получен по совместимому HTTP-маршруту на 127.0.0.1. Кэш содержит 370168 байт и совпадает с оригиналом. С пустым DEBUGINFOD_URLS символы не загружаются. Журналы — task04-package.log, task04-installed-with-dependencies.log, task04-debuginfod.log и task04-local-debuginfod.log.

## Сценарии GDB и Hasher

Оба сценария отработали по три раза и дали по три строки, совпадающие с эталонами. Порча эталона в отдельной копии дала код make 2, восстановление — 0. Команда из локального .gdbinit стала доступна после разрешения только конкретного файла через auto-load safe-path.

Без /proc GDB не установил точку останова, хотя пакетный сеанс вернул 0. До настройки запрос монтирования давал mount point is not allowed и код 1. После описания /proc в fstab Hasher, добавления allowed_mountpoints, перезапуска службы и запуска с --mountpoints=/proc GDB остановился в emit. В SPEC сборка с этим требованием использует BuildRequires: /proc. Два запуска prepare-hasher.sh в существующей среде сохранили пакеты.

Второе окружение создано с парой user_c/user_d. gdbserver в первом и GDB во втором соединены через loopback. Точка останова сработала, аргументы и исходник доступны. Протоколы — task07-hasher-server.log и task07-hasher-client.log.

При kernel.yama.ptrace_scope=1 подключение к отдельно запущенному собственному sleep дало Operation not permitted и код 1. GDB смог подключиться к собственному дочернему sleep при том же значении ядра. Изменение системного значения не выполнялось.

## Результат

Текущий прогон на стенде: PASS=10 FAIL=0 SKIP=0. Автоматизация воспроизводит локальные проверки и сверяет журналы опытов, зависящих от окружения. Приёмочная проверка опубликованного клона и публикация ещё впереди. Исходный опыт записи через неинициализированный указатель заменён опытом передачи неверного параметра.
