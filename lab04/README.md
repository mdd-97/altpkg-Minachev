## 1. Командная оболочка

| Команды | Класс | Пакет |
|---|---|---|
| read, printf | Встроенные команды Bash | bash |
| ll | Псевдоним ls -l, заданный для опыта | — |
| rpm, sed, grep | Внешние программы | rpm, sed, grep |

Команда type -a показывает возможные способы разрешения имени. Например, у printf также есть внешний вариант, но в Bash сначала выбирается встроенная команда. Владельцев внешних файлов проверил rpm -qf. Дочерняя оболочка получила LAB04_VALUE только после export. Изменение в дочернем процессе не изменило переменную родителя.

| Подстановка для one/two/three | Вывод |
|---|---|
| ${V#*/} | two/three |
| ${V##*/} | three |
| ${V%/*} | one/two |
| ${V%%/*} | one |

Перенаправления применяются слева направо. В `> combined 2>&1` stderr копирует уже перенаправленный stdout. В `2>&1 > stdout-only` stderr остаётся на прежней цели stdout. Без номера дескриптора `>` меняет только stdout. Файл combined содержит stdout и stderr, stdout-only — только stdout; stderr отдельно захвачен из исходного stdout в original-stdout. diff -u stdout-only combined показывает добавленную строку stderr и код 1. Дополнительный фактический пример: logs/review-redirection.log. Цикл читает имя назначения из встроенного документа и проверяет конвейер uname, head, cut, tr. Результат linux совпал с эталоном. Журнал — task01.log.

## 2. Временные файлы

mktemp выдаёт разные имена и создаёт файл с режимом 600. Каталог создаётся с 700: чтение и изменение доступны владельцу, для входа в каталог требуется бит исполнения. trap EXIT удаляет файл, обработчики INT и TERM завершают сценарий кодами 130 и 143. Наблюдающий процесс подтвердил существование файла до отправки сигналов и отсутствие после. Штатный код 0, предусмотренный аварийный код 7. mktemp -u печатает имя без резервирования, поэтому это только опыт. Шаблон dry.XXX содержит три X и принят с кодом 0, short.XX содержит два X и отклонён с кодом 1 и too few X. Режим файла 600 и каталога 700 теперь проверяется утверждениями, а не только выводится в журнал. Новая структурированная сводка в DOCX и logs/review-temp.log. Журнал — task02.log.

## 4. Список задач

Сценарий rdsu-tasks хранит TSV в `$XDG_CONFIG_HOME/rdsu-tasks` или в `~/.config/rdsu-tasks`. touch создаёт отсутствующий файл; для существующего обновляет временные метки и не меняет содержимое. Поэтому повторный запуск не обнуляет базу. Режимы add, done и list работают без dialog. Экранное меню получает выбор из stderr во временный файл. Массив аргументов Bash и подстановка "${array[@]}" передают каждый ID и текст целыми аргументами, включая пробелы. EXIT удаляет временные файлы. Три записи добавлены, одна отмечена. diff с tasks.expected завершился с кодом 0. Усиленная проверка env/check-menu.py запускает настоящий dialog в Hasher PTY: через меню добавляет Menu task with spaces, показывает список, отмечает задачу, проверяет список Done и завершение. Проверены строка базы 1/done/текст, код 0 и отсутствие временных файлов. Полный PTY-поток, начальный экран и функциональный протокол сохранены в logs/review-menu*. Журналы — task04-cli.log, task04-menu.log и протокол меню.

## 5. RPM

SPEC использует исходный сценарий напрямую и устанавливает его в %_bindir с режимом 755. BuildRequires и явных Requires нет. В отдельном Hasher дополнительно выполнена наблюдаемая сборка: временная копия SPEC проверяет rpm -q dialog в %build и прекращает сборку, если он установлен. Получено package dialog is not installed и OBSERVER_DIALOG_ABSENT; сборка успешна, автоматически вычислен Requires dialog. Результат совпал с исходным RPM по идентификатору, составу и зависимостям (три diff=0). Протоколы review-build-no-dialog.log и review-build-no-dialog-summary.log; воспроизводящий сценарий env/check-build-without-dialog.sh. Автоматический разбор строки интерпретатора и команд дал /bin/bash, coreutils, dialog, gawk, grep и sed. FINDPACKAGE-COMMANDS перечислил awk, dialog, grep, mkdir, mktemp, mv, rm, sed и touch. /bin/bash получен из строки интерпретатора; awk соответствует gawk, mkdir/mktemp/mv/rm/touch — одной зависимости coreutils, остальные команды — dialog, grep и sed. Requires содержит имена пакетов, а не отдельную запись на каждую команду. Установка без dialog отвергнута, после установки зависимости пакет установлен и запущен по имени в Hasher. Журналы — task05-build.log и task05-runtime.log.

## 8. Проверка

```sh
bash -n lab04/check/check-lab04.sh
lab04/check/check-lab04.sh
```

Сценарий сохраняет 12 именованных проверок и различает живые запуски и проверку сохранённых протоколов.

| № | Проверка | Режим и ресурс |
|---|---|---|
| 1 | Классы команд, export, подстановки, конвейер | Живая, локально |
| 2 | Временные файлы, ошибки, сигналы, права | Живая, локально |
| 3 | Текст, join и байты | Живая, локально |
| 4 | Несовместимый порядок сортировки | Живая, ru_RU.utf8 |
| 5 | CLI, пробелы, count | Живая, локально |
| 6 | moreutils | Сохранённый протокол |
| 7 | Операции меню и очистка | Живая, Hasher/PTY |
| 8 | Requires, точная версия установленного RPM и запуск | Живая, RPM/Hasher |
| 9 | Правило и оба тега GEAR | Живая, локальный GEAR |
| 10 | Сравнение двух RPM | Сохранённый протокол |
| 11 | Отказ старой count | Сохранённый протокол |
| 12 | Теги свежего публичного GEAR | Живая, сеть |

Переменные: LAB04_HASHER_WORKDIR, LAB04_RPM, LAB04_GEAR_REPO, LAB04_GEAR_URL. Каждая недоступная проверка получает собственный SKIP; проверки сохранённых протоколов явно помечены в выводе. RPM-проверка теперь сверяет NAME/VERSION/RELEASE/ARCH выбранного артефакта с установленным пакетом.

Усиленный сценарий дал 12/0/0. Подмена выбранного RPM версией 1.1 при установленной 1.0 дала FAIL 05, 11/1/0, код 1. Порча tasks.expected дала FAIL 04, 11/1/0 и код 1; после восстановления 12/0/0 и код 0. Полный протокол logs/review-summary.log. Основная версия ЛР4 подготовлена в dev. Свежий локальный клон прошёл полный прогон, отрицательные опыты и восстановление. Публикация последней версии и проверка свежего GitHub-клона фиксируются отдельно. Публичный GEAR содержит обе версии: 1.0-alt1 и 1.1-alt2. Приёмка преподавателем не подтверждена.

## Вывод

Оболочка связывает системные команды и запускает тесты с проверкой их кодов. Экранный интерфейс и неинтерактивный режим одного приложения используют одно хранилище. RPM вычисляет зависимости сценария, а GEAR воспроизводит сборку по тегу.
